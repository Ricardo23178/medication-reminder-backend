# Web 管理后台

依据毕业设计方案第十一项后台管理及第12周“Web管理端、统计与审计”，本阶段交付 Vue 3 + Element Plus 管理端和 Spring Boot 管理接口。

## 范围与权限

- 管理员登录和运行概览；用户数量、启用账号、未关闭异常、提醒任务、待投递及失败通知统计。
- 用户按账号/昵称与状态查询，启用或禁用普通账号。禁止修改管理员状态，不提供提权、改密码、删除用户或改用药计划接口。
- 字典、通知模板、投递参数管理；只允许修改固定键的值，采用版本检查拒绝覆盖其他管理员的新版本。
- 异常事件和通知投递状态只读查询，默认不展示药品、剂量、患者ID、接收人、消息正文或联系电话。
- 成功的用户状态和配置变更记录操作人、对象、原因、变更前后值和时间。审计与业务修改在同一服务事务内；失败校验不产生成功审计，不提供审计编辑删除接口。
- 每个受保护请求核对数据库中的当前用户与状态；后台额外要求当前角色为ADMIN，不仅信任JWT中的旧角色。禁用/逻辑删除后旧令牌的后续请求返回401，角色降为USER后后台返回403。

全局任务的已有演示接口仍沿用原权限；本阶段后台只查看状态，不增加手动执行全库任务入口。个人导出、账号注销、系统推送及手机/平板适配未纳入本阶段。

## 数据库与配置

`src/main/resources/db/admin-console.sql` 仅增加 `admin_setting` 和 `admin_audit_log`，不修改既有业务表结构或数据。启动初始化默认开启；CREATE IF NOT EXISTS与INSERT IGNORE保留已有配置，不重置管理员口令。由DBA手工执行脚本后，可用 `--app.initialize-console=false` 关闭启动DDL。初始化需要建表权限；该脚本是现有工程的增量脚本，不能替代仍缺失的全量基础建库脚本。

预置值及使用位置：

| 键 | 值格式 | 生效范围 |
| --- | --- | --- |
| `event.labels` | 含三种既有异常编码的JSON对象，各名称1至40字符 | 管理端异常类型展示 |
| `notification.owner` / `notification.family` | JSON对象，仅title和content，分别至多80和500字符 | 后续新入队的本人/家属通知；不改写历史消息，无表达式或占位符执行 |
| `delivery.paused` | true/false文本 | 下一批站内消息发布；当前在途批次继续，异常入队保持 |
| `delivery.batch-size` | 1至100整数文本 | 下一批投递查询上限 |

配置不改变原有授权、通知去重、三次失败上限或家属知晓/关闭语义。

## 接口

所有接口位于 `/api/admin` 且需Bearer令牌，响应沿用 `{code,message,data}`。未登录/账号失效为HTTP401；后台无权限为HTTP403；其他业务拒绝沿用响应体code。配置版本冲突或管理员状态保护为409；目标不存在为404；非法参数为400。

| 方法 | 相对路径 | 用途 |
| --- | --- | --- |
| GET | `/me`、`/overview` | 当前管理员安全投影、运行计数 |
| GET | `/users` | keyword/status筛选，用户安全字段投影 |
| PATCH | `/users/{id}/status` | `{status:0或1,reason}`，原因3至200字符；重复相同状态不重复记变更审计 |
| GET | `/settings?category=DICT或TEMPLATE或PARAM` | 固定配置列表 |
| PUT | `/settings/{id}` | `{value,version,reason}`，乐观版本检查 |
| GET | `/events`、`/notifications` | status筛选的最小运行元数据 |
| GET | `/audit-logs` | action筛选（USER_STATUS、SETTING_UPDATE）的只读审计 |

分页接口统一返回 `{items,total,page,pageSize}`，页码1至100000，每页1至50，默认第1页20条。过滤值使用参数绑定与枚举检查。列表按ID倒序；概览与分页总数为当前查询时刻的统计，未保证多个查询的共同快照。

## 运行与验收

后端按主README启动，Web端在 `admin-web` 运行 `npm ci`、`npm run dev`，打开 `http://127.0.0.1:5173/admin/`。页面使用既有管理员账号，不预填口令。详情见 `admin-web/README.md`。

实际观察到管理命名空间缺少保护时测试失败（期望HTTP403、实际200），实现后转绿。开启 `RUN_MYSQL_INTEGRATION_TESTS=true` 的完整Maven测试49项通过，包含管理员身份与运行概览、越权与角色伪造、路径参数、禁用旧JWT、状态/审计、版本冲突、分页/隐私投影、模板仅对新入队生效和已有家属协同回归。测试关闭定时任务，业务夹具事务回滚；新增管理表及默认配置是本阶段持久交付。

Web端8项Node测试验证会话与视图并发、非JSON401、权限验证和输入边界；真实Chrome在独立HTTP夹具下验证登录、用户禁用与原因、审计、配置保存、409、字典、通知、401清理及普通用户拒绝。浏览器不写真实业务数据，不能代替服务器的真实MySQL集成验证。桌面1440px和窄屏390px检查页面无横向溢出，表格允许内部横向滚动。

## 运行观察

上线后核对用户状态变化与审计一一对应，普通用户后台请求为403，禁用用户旧令牌为401。修改投递暂停开关和每批数量后，观察下一批通知行状态与数量；恢复时不应改写历史正文或倒退事件状态。若发现越权展示、无审计修改或通知异常，先停止管理端配置操作，并将 `delivery.paused` 设true保留现场；不要直接删审计或通知记录。数据库故障、实际事务并发压力和大数据量性能需在部署环境继续验证。
